# EmergencyLink 测试流程

## 1. 准备

编译：

```powershell
.\build\build.ps1
```

自检：

```powershell
$p = Start-Process -FilePath .\dist\EmergencyLink.exe -ArgumentList '--self-test' -PassThru -Wait
$p.ExitCode
```

返回码为 `0` 表示基础通信链路正常。

手动测试可以在一台电脑上打开多个 `EmergencyLink.exe` 窗口模拟多台电脑，也可以在局域网内多台电脑上测试。

## 2. 主办方电脑兼服务器测试

1. 打开第一个 exe。
2. 在“本机服务器”区域填写：
   - 房间名：`match-room`
   - 房间密码：`123456`
   - 端口：`5050`
   - 连麦次数：`3`
   - 同批时间：`30`
3. 点击 `主办方电脑兼服务器`。
4. 确认右侧连接状态显示已加入主办方。
5. 记录界面显示的服务器地址。

通过标准：

- 服务器地址正常显示。
- “现场状态/日志”中出现服务器启动和主办方加入记录。

## 3. 选手加入测试

1. 打开第二个 exe。
2. 服务器地址填写主办方电脑 IP，本机多开可填 `127.0.0.1`。
3. 端口填写 `5050`。
4. 房间名和密码与服务器一致。
5. 显示名称填写 `选手A`。
6. 角色选择 `选手-比赛`。
7. 点击连接。

通过标准：

- 选手端显示已加入。
- 主办方的在线成员列表出现 `选手-比赛 | 选手A | 在线`。

## 4. 队友加入测试

1. 打开第三个 exe。
2. 使用相同服务器地址、端口、房间名和密码。
3. 显示名称填写 `队友B`。
4. 角色选择 `选手-队友`。
5. 点击连接。

通过标准：

- 队友端目标选手下拉框可以看到 `选手A`。
- 主办方在线成员列表出现 `选手-队友 | 队友B | 在线`。

## 5. 赛前测试通讯

1. 主办方在“管理/审批”页点击 `赛前测试`。
2. 队友端选择 `选手A`。
3. 点击 `确认发送测试提醒`。
4. 在二次确认窗口点击确认。
5. 观察选手端。
6. 选手按 `Ctrl + Alt + R` 或点击主窗口的 `已收到`。

通过标准：

- 选手悬浮件蓝色/黄色闪烁。
- 能听到提示音。
- 选手回执后，主办方和队友能看到已回执状态。
- 连麦剩余次数不减少。

## 6. 比赛中正式告警

1. 主办方点击 `比赛中`。
2. 队友端确认测试按钮不可用。
3. 队友端选择 `选手A`。
4. 点击 `确认发起正式告警`。
5. 在二次确认窗口点击确认。
6. 选手观察红色悬浮提醒和声音。
7. 选手发送回执。
8. 主办方选中该正式请求。
9. 点击 `同意选中正式请求`。

通过标准：

- 测试通讯在比赛中关闭。
- 正式告警必须二次确认。
- 选手端红色闪烁并播放声音。
- 选手回执状态同步显示。
- 主办方同意后，已用次数 +1，剩余次数 -1。

## 7. 同批提醒合并测试

1. 保持阶段为 `比赛中`。
2. 队友端连续两次点击正式告警并确认，间隔小于“同批时间”。
3. 查看主办方“提醒批次”列表。

通过标准：

- 不应新增两个独立正式请求。
- 同一批次的提醒次数增加。
- 选手端会再次触发声音和动画。
- 主办方同意该批次后只扣减一次。

## 8. 超额紧急请求测试

1. 将连麦次数调整为 `1` 并点击 `应用配置`。
2. 发起并同意一次正式请求，使剩余次数变为 `0`。
3. 队友再次发起正式告警。
4. 主办方选中该请求并同意。

通过标准：

- 剩余次数为 0 时，队友仍可发起请求。
- 主办方同意时提示超额紧急请求。
- 剩余次数保持 0。
- 超额批准次数 +1。
- 日志中记录超额批准。

## 9. 管理者兜底服务器测试

1. 关闭所有客户端。
2. 在服务器电脑点击 `停止服务器`。
3. 重新打开一个 exe。
4. 点击 `管理者兜底服务器`。
5. 再打开一个 exe，角色选择 `主办方` 连接该服务器。
6. 再打开选手端和队友端连接。
7. 重复正式告警流程。
8. 分别用主办方和管理者点击同意测试。

通过标准：

- 管理者电脑可以作为服务器。
- 主办方电脑可以只作为审批端。
- 管理者审批时日志记录为“管理者代审批同意”。

## 10. 异常流程测试

### 密码错误

使用错误密码连接。

通过标准：

- 客户端提示房间名或密码不正确。
- 不应出现在在线成员列表中。

### 断线重连

关闭选手端，再重新打开并连接。

通过标准：

- 主办方日志出现离线和重新加入。
- 重新加入后目标选手下拉框恢复显示。

### 阶段限制

在准备中或已结束阶段尝试发送提醒。

通过标准：

- 测试提醒只能在赛前测试阶段发送。
- 正式告警只能在比赛中发送。

## 11. 日志检查

测试完成后查看：

```text
dist\Data\audit-yyyyMMdd.log
```

通过标准：

- 能看到成员加入、阶段切换、提醒发起、回执、审批、扣次、超额等记录。
